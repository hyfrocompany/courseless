# PRODUCT.md — Courseless

## What it is
Courseless is a desktop app that turns "I want to be able to do X" into a step-by-step
guided path through the real task in the real app. No videos, no courses: an on-demand
lesson (6–12 steps) is generated by a local AI engine, run inside a focused runner or a
compact always-on-top float widget, with per-step checkpoints, escalating hints, a
contextual coach chat, and honest improvement stats.

## Users and jobs
Primary: individuals teaching themselves real tools (Excel, Figma, git, NetSuite, an
internal CRM) at their own pace — learner-pays, self-serve. Secondary (later): teams
onboarding new hires with shared lesson libraries. Individual-first is a confirmed
positioning decision (2026-08).

Job: "get me from never-done-it to done-it, in the tool, faster than a tutorial."
Success: the user completes the real task with fewer hints each run (assistance rate
falls), not merely watches or completes a quiz.

## Mechanism and position
- Lessons are compiled on demand, not recorded or authored ahead: any task anyone can
  name, day one, always current. There is no library cold start: the catalogue is as
  large as what people ask for.
- Guidance, not agency: the AI never does the task for the user. Stated ideology:
  "when an agent does it for you, the skill stays the machine's."
- Pedagogy commitments (research-backed, durable): learning-by-doing over watching;
  faded worked examples (per-step fade_tier 1→3, hand-holding decreases); observable
  checkpoints per step ("You should see…"); assistance rate (hints + 2×skips per step)
  is the honest metric — never completion-time-vs-expert.
- Quiet by default: text-first coaching, no voice, keyboard-first (Space/H/S/C).

## Engine (deliberately abstracted)
Current engine: the user's local Codex CLI (spawned via app-server JSON-RPC with exec
fallback) — chosen for zero-key, zero-account local bootstrapping. This is a test/bridge
engine: the product plans to swap/add hosted LLM APIs (e.g. DeepSeek) behind the same
CodexService-shaped interface. UI copy must therefore stay provider-neutral ("your
coach", "engine"); provider names appear only in Settings detection detail and setup
instructions. Courseless never holds an API key for the local engine.

## Durable constraints and facts
- Local-only: lessons/settings are plain JSON under the user's data folder; no accounts,
  no server, no telemetry. "Yours, on this machine" is a product promise.
- Starter library: 27 built-in generated lessons across 10 tracks (Claude Code,
  Photoshop, Excel, Figma, NetSuite, Salesforce, Notion, Blender, Premiere, Onboarding);
  first run never looks empty. Users can delete builtins (tombstoned) and regenerate.
- Windows-first Electron (main window + frameless always-on-top float + tray +
  global hotkey Ctrl+Shift+Space); cross-platform where free.
- Keyboard-first is an accessibility commitment: every lesson completable without mouse.
- Copy voice: confident, quiet, zero exclamation marks ("Teach me", "Did it", "Stuck?").
- Binding visual constraints volunteered by the owner: ocean-blue identity (not purple),
  ocean-gradient lesson covers are brand and stay; library lists lessons as dense rows
  with cover-cards reserved for Featured; typography soft/professional, "not as sharp".

## Platform
web (Electron renderer; desktop app shell). Modes: app UI is Operate; first-run is
Onboard-flavored Operate.

## Stack
Electron + electron-vite, React 18, TypeScript, Tailwind v4; fonts self-hosted
(Newsreader / Manrope / JetBrains Mono). Main-process services: CodexService (engine),
LessonStore, SettingsStore. Confirmed 2026-08.
